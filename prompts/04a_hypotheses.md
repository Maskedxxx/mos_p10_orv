По одному вердикту «нарушен» сформулируй проверяемые гипотезы о последствиях для адресатов акта.

Вход: полный текст акта; целевая справка из паспорта; карточка вердикта и переданные конкретные замечания проверки (отдельный JSON-блок). Справка — подсказка: при расхождении с актом используй текст и укажи расхождение в why_this_many. Инструментов нет; источники данных только предлагаются, а не проверяются внешним поиском.

Метки входа: «## ПОЛНЫЙ ТЕКСТ АКТА», «## ПАСПОРТ АКТА», «## КАРТОЧКА ВЕРДИКТА (JSON)».
Справка содержит requisites.developers, status, addressee, procedure.{state, participants, result, clauses},
documents.items, deadlines.items, allocation и control. Остальные поля паспорта не переданы.
Данные и инструменты других узлов для решения этой задачи не предполагаются.

Порядок работы:
1. Прими нарушение из карточки как исходное условие. Не переоценивай вердикт, не добавляй новых нарушений и рекомендаций по изменению акта. Учти все конкретные замечания, переданные с карточкой; объединение одного механизма допустимо, объясни охват замечаний в why_this_many.
2. Определи род нарушения по описанию violation_kind. Для дефекта нормы не придумывай затраты, возникающие из самого отсутствия срока, определения или ясности.
3. Выдели самостоятельные механизмы. Один механизм — одна гипотеза; затраты разных сторон одного механизма — эффекты внутри неё. Разные показатели или источники одного последствия сами по себе не образуют новую гипотезу или новый эффект. Объясни количество гипотез в why_this_many.
4. Назови затронутых адресатов, условия применения и масштаб, подтверждаемый входом. Если масштаб неизвестен, так и укажи; общую статистику нельзя выдавать за фактическое число затронутых без обоснованной связи. Для проекта и ещё не вступивших положений описывай ожидаемое применение, не запрашивай несуществующую статистику их исполнения.
5. Для каждого эффекта укажи способ расчёта и данные по правилам полей. Неизвестные числа не превращай в факты; допущения обозначай явно. Данные запрашивай у органа, который ведёт соответствующую процедуру; пустой список исполнителей не оправдывает автоматическую подстановку органа, принявшего акт. Если порядок исполнения ещё не определён, не выдумывай стоимость по случайным аналогам.
   Перед ответом сверь метод со списком данных: для связанных случаев нужны связи,
   для причинного вывода — основания, а не только общий счётчик. Не выдавай
   экспертную квалификацию причины за заведомо регистрируемое органом число.
6. Укажи, какой факт поддержит или опровергнет механизм; рост или снижение показателя используй только с объяснением связи. Измерение масштаба само по себе не доказывает избыточность или причинность.
7. Сохрани основания из карточки и точные цитаты/пункты акта. Заполни полный ответ и краткие выжимки по схеме; выжимки не должны вводить новые утверждения или терять существенные оговорки.

Верни только JSON по схеме ответа. Требования к отдельным полям, источникам чисел, вопросам органу и формату определены в описаниях полей.
