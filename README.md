# Платформа ОРВ · модуль П-10

Сервис разбирает нормативный правовой акт города Москвы и возвращает
готовый Excel: **карту гипотез** — что в акте не так и чем это измерить,
и **запрос показателей** — что спросить у органа-разработчика.

Это работа, которую аналитик оценки регулирующего воздействия делает
вручную несколько дней. Сервис делает её за 15–20 минут, а человек
проверяет результат.

Заказчик — АНО «Мосстратегия» / Департамент экономической политики
и развития города Москвы.

---

## Что на входе и что на выходе

**Вход** — файл акта: `.docx`, `.pdf` или `.doc`. Формат неважен,
сервис определяет его сам.

**Выход** — один файл `.xlsx` с четырьмя листами:

| Лист | Что на нём |
|---|---|
| Карта гипотез | индикаторы с претензией: что не так, к чему приводит, чем измеряется, какие нужны данные, на чём основан вывод |
| Запрос показателей | пустой бланк для органа: что посчитать, за какие годы, ради какой гипотезы |
| Нарушений не найдено | индикаторы, по которым гипотез не строили — с обоснованием и цитатой |
| Ошибки прогона | что не отработало; пусто — значит разбор прошёл целиком |

У каждого листа сверху одна строка-подпись: что на нём лежит и по какому
принципу отобрано. Первые два листа проверяют весь акт, вторые два —
показывают, что ни один из двенадцати индикаторов не потерялся по дороге.

**Листы связаны в обе стороны.** В карте у каждой гипотезы стоят номера
строк запроса, которыми она закрывается. В запросе у каждого показателя —
номера строк карты и индикаторы, ради которых его спрашивают. Получив от
органа цифры, аналитик сразу видит, к какой гипотезе они относятся, а не
перебирает карту вручную.

**Данные каждой гипотезы разделены на две группы.** Сверху то, что
запрашивают у органа, ниже открытые источники с адресом, откуда их взять
(torgi.gov.ru, прайсы, реестры). В запрос уходит только первая группа:
лист отправляют наружу, и всё напечатанное в нём орган читает как задание
себе.

**Колонка «На чём основано» — доказательная база вывода.** Дословная
цитата из акта с номером пункта, а под ней адреса внешних источников,
если индикатор ходил в интернет. Цитаты может не быть — тогда клетка
прямо говорит почему, а не остаётся пустой.

## Природа задачи

Есть методика АНО «Мосстратегия»: **двенадцать индикаторов эффективного
регулирования**. Это двенадцать вопросов, которые задают любому акту —
не требуют ли лишних бумаг, можно ли подать документы электронно, не
ссылается ли акт на отменённые нормы, и так далее.

Аналитик читает акт и отвечает на каждый вопрос. Там, где ответ «нарушено»,
он формулирует гипотезу: к чему это приводит, кого задевает, каким
показателем это измерить и где взять цифры. Часть цифр есть в открытых
источниках, часть надо запрашивать у органа — из них и складывается запрос.

Сервис повторяет эту работу.

**Ключевое решение — декомпозиция.** Акт не отдаётся одной модели с просьбой
«найди всё, что не так»: такой ответ приходит быстро, но получается
поверхностным, без опоры на текст. Вместо этого каждый индикатор проверяет
отдельный вызов модели со своей инструкцией, и каждый обязан подкрепить
вывод **дословной цитатой с номером пункта**. Без цитаты вердикт не
принимается — эксперту нечего было бы проверять.

### Что делает каждый узел

**1. Конвертация.** Файл превращается в размеченный текст. Нумерация
пунктов, заголовки и таблицы сохраняются — без номеров пунктов дальше
нечем будет сослаться на конкретное место акта. Работает `docling`, он
сам определяет формат по содержимому. Устаревший `.doc` сначала
перегоняется в `.docx` через LibreOffice.

**2. Саммари.** Реквизиты акта, что регулирует, кого касается, что требует,
и все числовые значения с указанием пунктов. Уходит в шапку итогового
файла. Агентам-индикаторам **не подаётся**: пруф должен быть дословной
цитатой, а в саммари пересказ, цитировать оттуда нечего.

**3. Вердикты.** Двенадцать вызовов модели одновременно, у каждого своя
инструкция: что искать, что считать нарушением, а что нарушением *не*
является. Восемь из двенадцати при необходимости ищут данные во внешних
источниках. Проверки не видят друг друга — это защищает от того, чтобы
одна догадка потянула за собой остальные.

**4. Разбор корзины.** Чистый код, раскладывает двенадцать вердиктов
по четырём кучам. Ничего не выбрасывается: все двенадцать доходят до
итогового файла, просто на разные листы.

**5а и 5б. Гипотезы.** Две ветки идут одновременно. Из нарушений пишутся
гипотезы с цитатой; из пробелов в данных — гипотезы-подозрения без цитаты,
зато с подробным перечнем того, что запросить у органа.

**6. Сборка карты.** Проверки работали порознь, поэтому разные индикаторы
могли зацепить одну проблему с разных сторон. Здесь модель впервые видит
все гипотезы разом и сливает повторы, сохраняя оба индикатора, обе цитаты,
оба набора данных. Самый долгий шаг разбора.

**7. Запрос показателей.** Из карты отбирается то, чего нет в открытом
доступе, и склеивается по смыслу: если три гипотезы просят «количество
заявок» разными словами, чиновник должен увидеть один вопрос. Глубина
запроса — три последних завершённых года.

**8. Excel.** Четыре листа плюс обратные ссылки между картой и запросом.

## Двенадцать индикаторов

Список закреплён методикой и одинаков для всех актов. Четыре вопроса
решаются по тексту акта, восемь требуют данных извне.

| № | Что проверяется | Где ищется ответ |
|---|---|---|
| 1 | Орган сам запрашивает документы, которые у государства уже есть | текст |
| 2 | Документы можно подать электронно | текст |
| 3 | Акт не ссылается на отменённые нормы и упразднённые органы | текст + интернет |
| 4 | Требования не продублированы в других актах | текст + интернет |
| 5 | Ошибку в пакете можно исправить, а не подавать всё заново | текст |
| 6 | У обязательного требования есть срок действия | текст |
| 7 | В процедуре нет шагов, не влияющих на решение | текст + интернет |
| 8 | С заявителя не требуют лишних документов | текст + интернет |
| 9 | Из текста понятно, что требуется и что будет за невыполнение | текст + интернет |
| 10 | Норма реально работает, а не существует на бумаге | текст + интернет |
| 11 | Сроки не затянуты по сравнению с другими регионами | текст + интернет |
| 12 | Требования не отсекают часть участников без оснований | текст + интернет |

Для индикаторов 7, 8 и 11 сравнение идёт с семью субъектами: Санкт-Петербург,
Московская область, Татарстан, Свердловская, Новосибирская, Нижегородская
области, Краснодарский край.

## Четыре вердикта и что из них следует

Это главная развилка пайплайна. От вердикта зависит, куда пойдёт индикатор.

| Вердикт | Что означает | Куда идёт |
|---|---|---|
| **нарушен** | проблема найдена в тексте, есть цитата и пункт | → гипотеза → карта |
| **нет данных** | тема есть, но проверить нечем | → гипотеза-подозрение → карта → **запрос органу** |
| **соблюдён** | требование выполнено, тоже с цитатой | → лист «Нарушений не найдено» |
| **не применимо** | темы в акте нет и быть не должно | → лист «Нарушений не найдено» |
| **ошибка** | проверка сорвалась, попытки исчерпаны | → лист «Ошибки прогона» |

Три правила, которые заложены намеренно:

**«Нет данных» никогда не превращается в «нарушен».** Обвинить акт там,
где его просто не проверили, — худшая из возможных ошибок: разбираться
с несуществующей проблемой будут живые люди.

**Сорвавшаяся проверка никогда не превращается в «соблюдён».** Молча
проглоченный сбой дал бы акту зелёный свет там, где его не проверяли.
Поэтому есть отдельный статус «ошибка» и отдельный лист под него.

**Гипотеза не попадает в карту, если для неё нельзя назвать показатель
эффекта и источник данных.** Это тормоз против разрастания: у коллег из
ВШЭ без такого ограничения вышло 39 карточек вместо десяти.

## Устройство репозитория

```
app/
  contracts.py      pydantic-модели всех входов и выходов
  config.py         12 индикаторов, маршруты, модель, лимиты
  logger.py         лог на каждый прогон
  trace.py          артефакты прогона, атомарная запись
  runner.py         обёртка над claude -p: схема, ретраи, стоимость
  nodes/            восемь узлов пайплайна, по файлу на узел
  pipeline.py       оркестратор: порядок, барьеры, прогресс
  web.py            веб-страница на NiceGUI, вход по паролю, очередь
prompts/            17 промптов, по файлу на вызов модели
tests/              293 теста
deploy/             systemd-юнит
```

**Промпты лежат файлами, а не в коде.** Их правят люди, не разбирающиеся
в Python, и правят часто — это бизнес-логика, а не программирование.

**Контракты обязательны на каждой границе.** Узел принимает и возвращает
pydantic-модель, а не словарь. Все поля моделей — латиницей: `claude -p`
отвергает кириллические имена полей в JSON-схеме.

## Артефакты прогона

Каждый прогон складывается в отдельную папку `runs/<id>/`:

```
00_input.pdf              исходный файл как загрузили
01_document.md            текст акта после конвертации
02_summary.md             саммари
03_verdicts/01…12.json    вердикты по индикаторам
03_verdicts/*.raw.json    сырые ответы модели, включая упавшие попытки
04_buckets.json           четыре кучи
05_hypotheses/*.json      гипотезы
06_map.json               карта после слияния
07_request.json           запрос показателей
08_result.xlsx            итог
progress.json             ход прогона, читает веб-страница
run.log                   лог всех узлов
meta.json                 время, стоимость, статус
```

**Сырые ответы модели сохраняются всегда**, включая попытки, которые
не прошли проверку. Без них нечем разбираться, почему модель ответила
не так.

## Как запустить

Нужен Python 3.12 и установленный `claude` CLI с доступом к API.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# доступ к веб-странице
cat > .env.secrets <<EOF
P10_AUTH_USER=admin
P10_AUTH_PASSWORD=<пароль>
P10_STORAGE_SECRET=<случайная строка>
EOF
chmod 600 .env.secrets

.venv/bin/python -m app.web        # страница на порту 8030
```

Без заполненного `.env.secrets` сервис не стартует — это сделано намеренно,
чтобы страница не поднялась нараспашку.

Тесты:

```bash
.venv/bin/pytest -q -m "not live"   # без обращений к модели
.venv/bin/pytest -q -m live         # с реальными вызовами, платно
```

## Настройки

Всё в `app/config.py`:

| Что | Значение | Зачем |
|---|---|---|
| `MODEL` / `EFFORT` | `sonnet` / `medium` | задано явно: иначе CLI возьмёт модель из настроек машины |
| `MAX_CONCURRENT_RUNS` | `2` | одновременных разборов; третий встаёт в очередь |
| `REQUEST_YEARS_DEPTH` | `3` | глубина запроса в годах, текущий год не берётся |
| `ACCEPTED_EXTENSIONS` | `.docx .pdf .doc` | принимаемые форматы |

## Чего пока нет

- **Ветка ГАРАНТ.** Индикаторы 3 и 4 сейчас ищут в открытом интернете.
  С подключением правовой базы у них появится второй источник — связи
  документа. Шаги 6, 7 и 8 при этом не меняются.
- **Второй прогон после ответа органа.** Вердикты «нет данных» должны
  пересчитываться, когда придут запрошенные цифры.
- **Суточный лимит.** Ограничена только одновременность, счётчика за сутки
  нет.
- **Автозапуск.** Сервис и туннель поднимаются вручную, systemd-юнит лежит
  в `deploy/`, но не установлен.
