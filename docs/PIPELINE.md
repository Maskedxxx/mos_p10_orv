# Карта процесса П-10

Этот документ — указатель по текущему коду, а не копия методики. Правила проверки и описания полей находятся в [prompts/](../prompts/) и [app/contracts.py](../app/contracts.py). Состояние конкретного запуска определяйте по его артефактам, а не по этому описанию.

```text
Загрузка → текст → паспорт → 12 вердиктов → сортировка
                                              ├─ нарушен ──→ гипотезы ─┐
                                              └─ нет данных → вопросы ─┤
                                                                       ↓
                                                            карта → запрос → Excel
```

За очередью следит [app/run_queue.py](../app/run_queue.py), порядок узлов задаёт [app/pipeline.py](../app/pipeline.py). Веб-страница — [app/web.py](../app/web.py). Полный текст акта передаётся индикаторам; вместо полного паспорта каждый получает выбранную справку из [app/input_contexts.py](../app/input_contexts.py). Отсутствие поля в справке не означает отсутствия информации в акте.

## Узлы по порядку

| Шаг | Вход и задача | Выход и следующий шаг | Код / инструкция |
|---|---|---|---|
| 1. Чтение | Загруженный `.pdf`, `.docx` или `.doc`. Docling извлекает текст; для `.doc` сначала используется LibreOffice. | `01_document.md` → паспорт и последующие узлы. | [convert.py](../app/nodes/convert.py) |
| 2. Паспорт | Полный текст акта; модель выделяет реквизиты, адресатов, обязанности, документы, сроки, ссылки и другие разделы. | `02_passport.json` → справки индикаторов, гипотез и запроса. Сырой ответ — `02_passport.raw.json`. | [passport.py](../app/nodes/passport.py), [01_passport.md](../prompts/01_passport.md), `ActPassportOutput` в [contracts.py](../app/contracts.py) |
| 3. Вердикты | Полный текст, справка паспорта и индивидуальное задание. 12 агентов работают параллельно; 3, 4, 10, 11 имеют инструменты поиска. | `03_verdicts/NN.json` — вердикт; `NN.checks.json` — таблица проверок; `NN.stream.jsonl` и `NN.raw.json` — трасса и сырой ответ. | [verdicts.py](../app/nodes/verdicts.py), `02_indicator_01.md` … `02_indicator_12.md` в [prompts/](../prompts/), `Indicator01Output` … `Indicator12Output` |
| 4. Сортировка | Python распределяет вердикты по группам. | `04_buckets.json` → ветки гипотез; «соблюдён» и «не применимо» находятся в общей группе проверенных, ошибки — отдельно. | [sort.py](../app/nodes/sort.py), `Buckets` |
| 5. Гипотезы | По вердиктам «нарушен» — возможные механизмы и данные; по применимым «нет данных» — вопросы о недостающей практике. Две ветки выполняются одновременно, внутри ветки — отдельный вызов по вердикту. | `05_hypotheses/NN.json` → карта. Для индикаторов 1–6 и 11 «нет данных» означает незавершённую правовую проверку: практическая гипотеза не строится, в Excel появляется ручная проверка. | [hypotheses.py](../app/nodes/hypotheses.py), [04a](../prompts/04a_hypotheses.md), [04b](../prompts/04b_hypotheses.md), `HypothesisSetOutput` |
| 6. Карта | Все сформированные гипотезы; один вызов модели сравнивает их и может объединить полные дубли. Полный акт этому вызову не передаётся. | `06_map.json` → запрос. Частичные пересечения сохраняются с пояснением. При сбое вызова предусмотрена карта из входящих гипотез без слияний. | [merge.py](../app/nodes/merge.py), [05_merge.md](../prompts/05_merge.md), `MergeOutput` |
| 7. Запрос | Выбранные данные карты, текст акта, справка паспорта, годы и обязательные показатели выбранного типа акта. | `07_request.json` → Excel. При дополнении существующего запроса используется дополнительная инструкция. | [request.py](../app/nodes/request.py), [06_request.md](../prompts/06_request.md), [06_request_append.md](../prompts/06_request_append.md), `RequestOutput` |
| 8. Excel | Готовые карта, запрос, группы вердиктов и паспорт; Python формирует книгу. | `08_result.xlsx` → эксперт, скачивание и диалог. | [excel.py](../app/nodes/excel.py) |

Ветви гипотез, карта или запрос могут завершиться частично при ошибке. Успешное создание Excel и статус «готов» не означают, что все выводы верны и все источники прочитаны. Проверяйте статусы узлов, лист «Ошибки прогона» и доказательства.

## Индикаторы и инструменты

| № | Проверка | Источники агента |
|---:|---|---|
| 1 | Межведомственное взаимодействие | Текст акта |
| 2 | Электронная подача | Текст акта |
| 3 | Актуальность актов и органов | Текст, ГАРАНТ, интернет |
| 4 | Дублирование требований | Текст, ГАРАНТ, интернет |
| 5 | Доработка пакета | Текст акта |
| 6 | Срок действия требования | Текст акта |
| 7 | Избыточные процедуры | Текст акта |
| 8 | Оптимальный пакет документов | Текст акта |
| 9 | Понятность требований | Текст акта |
| 10 | Практика применения | Текст, ГАРАНТ, интернет |
| 11 | Приемлемые сроки | Текст, ГАРАНТ, интернет |
| 12 | Ограничение конкуренции | Текст акта |

Список задаётся в [app/config.py](../app/config.py); доступные методы ГАРАНТа различаются по индикаторам. Агент паспорта также может использовать `garant_search`, если токен доступен. Сами диалог и ГАРАНТ-помощник имеют собственные разрешённые инструменты.

Правила, важные при чтении результатов:

- Само повторение нормы другого акта не считается нарушением индикатора 4. В текущем контракте № 4 из такого повтора вердикт «нарушен» не следует; непрочитанная необходимая норма остаётся «нет данных».
- У индикатора 8 сомнение не должно автоматически превращаться в лишний документ. Его текущий контракт не предусматривает «нет данных»: осторожная отметка сама по себе не доказывает фактическую необходимость документа.
- Для сроков разные единицы сами по себе не доказывают превышение. Сравниваются действие, условия, единицы и начало отсчёта; непрочитанный необходимый федеральный предел — не подтверждение соблюдения.

## Как читается ГАРАНТ

```text
Реквизиты → API ГАРАНТа: поиск ID и редакции
          → при необходимости: браузер интернет-версии
          → блок / часть / поиск → прочитанный текст и ссылка
```

[garant_proxy.py](../app/garant_proxy.py) создаёт конфигурацию инструментов по узлу. Для индикатора 3 [mcp_garant.py](../app/mcp_garant.py) кэширует точные успешные запросы в пределах вызова и убирает из ответа редакций только `rs_Old`; другие записи остаются. Технический HTML вместо ответа не кэшируется как успех.

[mcp_garant_web.py](../app/mcp_garant_web.py) вызывает [garant_web.cjs](../scripts/garant_web.cjs) в контейнере `p10-garant-browser`. Запросы `block`, `page` и `search` могут требовать продолжения; таблицы передаются текстом, но содержимое изображений не извлекается и отражается в предупреждениях. Ошибка, непрочитанная часть или истёкшая сессия не доказывают отсутствие документа. Найденный публичный URL не гарантирует, что его номер совпадает с ID интернет-системы.

Индикатору 4 доступен платный `garant_export_block_html`: инструкция просит сначала использовать доступное веб-чтение и ограничивает выгрузку одной за проверку; это указание модели, а не отдельная гарантия на уровне данного описания. Остаток общей квоты можно увидеть в ГАРАНТ-помощнике.

## Артефакты прогона

```text
runs/<run_id>/
├── 00_input.<расширение>      исходный файл
├── 01_document.md             извлечённый текст
├── 02_passport.json           паспорт
├── 03_verdicts/               NN.json, NN.checks.json, сырые ответы и события
├── 04_buckets.json            группы вердиктов
├── 05_hypotheses/             гипотезы по индикаторам
├── 06_map.json                карта гипотез
├── 07_request.json            запрос показателей и вопросы
├── 08_result.xlsx             итоговая книга
├── meta.json                  настройки и происхождение модели
├── progress.json, run.log     состояние узлов и журнал
├── events.jsonl               события агентов и артефактов
└── _codex/, _garant/          служебные данные вызовов и ГАРАНТа
```

Сырой ответ и поток событий помогают отличить ошибку источника, ошибку модели и ошибку проверки схемы. Для Codex его рабочие входы, схемы и команды хранятся в `_codex/workspace/`; конкретные файлы вызовов могут отличаться. При необходимости используйте `scripts/watch.py` и `scripts/session_report.py`.

## Что происходит при сбое

- Если текст акта или паспорт не получен, основной прогон останавливается.
- Ошибка отдельного индикатора записывается как «ошибка» и не равна «нет данных».
- При неуспешном слиянии карта может быть собрана без слияний; при сбое запроса возможен пустой запрос. Проверяйте журнал и содержимое, а не только статус.
- Код проверяет схемы и отдельные связи между результатами; это не доказывает юридическую корректность ответа и не заменяет чтение источника экспертом.
